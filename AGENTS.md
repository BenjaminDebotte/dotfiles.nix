# Project: NixOS Dotfiles

## AI Agent Guardrails & Conventions
This repository contains a declarative NixOS and Home Manager configuration using Flakes. AI agents operating in this repository must strictly adhere to the following rules.

## Core Philosophy: Declarative over Imperative
- **NEVER** use standard Linux package managers (`apt`, `pacman`, `dnf`, `yum`, etc.).
- **NEVER** suggest imperative configuration changes like writing directly to `/etc/...` or using `systemctl enable`.
- **ALL** changes must be made declaratively via Nix expressions.

## Scope & Structure Boundaries
This repository is organized into three main scopes:

1. **`nix/` (Repository-level Tools & Overlays):**
   - `nix/dev.nix`: DevShell, Treefmt, and pre-commit checks (`deadnix`, `statix`, `treefmt`).
   - `nix/overlays.nix`: Centralized overlays attaching `unstable`, `neovim-nightly`, `herdr`, and `firefox-addons` directly onto `pkgs`.

2. **`system/` (System-Level NixOS Configuration):**
   - Use for: System services (systemd, ssh, docker/podman), kernel parameters, bootloaders, drivers, display managers (SDDM), network configurations, and Home Manager integration (`system/modules/home-manager.nix`).
   - `system/iso.nix`: Standalone Live USB installer image configuration.
   - **BANNED:** Never edit `system/hardware-configuration.nix`. This file is generated by NixOS and is machine-specific. Do not touch it.

3. **`home/` (User-Level Home Manager Configuration):**
   - Use for: User-specific programs (CLI tools, browsers), dotfiles (`home/config/`), themes, shell configurations (zsh, bash), and user environments.
   - Files are located in `home/user/` (e.g., `programs.nix`).

**Package Consumption Convention:**
External flake packages and unstable packages are exposed via `pkgs.*` overlays (e.g., `pkgs.unstable.vesktop`, `pkgs.neovim-nightly`, `pkgs.herdr`). Do not reference `inputs.*.packages` or ad-hoc `pkgs-unstable` in individual module files.

## Execution & Deployment Constraints
- **NEVER** run deployment commands autonomously (e.g., `nh os switch`, `nixos-rebuild switch`, `home-manager switch`, `nh os boot`).
- Applying changes to the live system is strictly the human's job.
- You are allowed to test syntax and evaluate the flake using safe commands like:
  - `nix flake check`
  - `nix-instantiate --parse <file>`
  - `nix eval .#<target>`

## Formatting & Linting
- All Nix files must be formatted with `nix fmt` (using Alejandra via `treefmt-nix`).
- Pre-commit hooks verify formatting (`treefmt`), dead code (`deadnix`), and anti-patterns (`statix`).

## Secrets
- **BANNED:** Do not modify, commit, or print secrets, private keys, or passwords.

## Summary Checklist for AI Actions:
1. Did I write declarative Nix code?
2. Did I place the change in the correct folder (`nix/`, `system/` vs `home/`)?
3. Did I avoid touching `hardware-configuration.nix`?
4. Did I consume packages through `pkgs.*`?
5. Did I stop before running `nh os switch` or `nixos-rebuild`?
